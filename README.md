# AI Helper In Minecraft

**当前版本：v0.3.1**（语义化版本；历史版本编号已统一改写，对照表见[更新日志](#更新日志)）

一个"无客户端"的 Minecraft AI 玩家：不需要打开游戏本体，用 GUI 控制 mineflayer 引擎进入服务器，由大模型驱动它在游戏内与人聊天互动。

- 入口为 Python tkinter GUI（多标签页：设置 / AI 配置 / 玩家配置 / 文档转书 / 点歌 / 杂项 / 玩家资料库 / QQ 转述 / 重连·踢出 / 界面美化 / 日志），后台由 Node.js（mineflayer）负责连接与协议。
- 支持 **离线 / LittleSkin / 正版(微软账号)** 三种登录方式。
- 登录失效时自动重新登录（LittleSkin 自动打开浏览器 OAuth，完成后自动重连）。
- 附带可选辅助功能：Quiz 自动答题、AutoEat 自动进食（自旧 Cubex 机器人项目保留）。

> 本项目仅供学习与个人使用。使用前请阅读文末[免责声明](#免责声明)。



## 功能特性

- 三种登录方式
  - 离线模式：仅填玩家名即可进入离线服务器。
  - LittleSkin：支持自定义皮肤站站点地址 / OAuth Client ID / Secret / 回调端口（默认 littleskin.cn），`3rdparty_auth.js` 完成 OAuth 登录并把 yggdrasil 会话写入 `auth_profile.json`。
  - 正版（微软账户）：`msa_auth.js` 使用设备码流程登录，凭据缓存在本机，之后自动静默登录。
- AI 玩家对话（OpenAI 兼容端点，支持 Anthropic）
  - 系统提示词 + 模板管理、上下文窗口、回复条数/字数限制。
  - 触发回复：多个触发词用英文逗号分隔；形如 `[名字]` 的单独触发词按**字面量**匹配（自动转义、忽略大小写），其它写法按完整正则匹配。检测对象为聊天框里的**完整原文**（含频道 / 称号 / 前缀），命中任一即回复。
  - 自动回复、定时回复、冷却时间。
  - 消息过滤正则、玩家黑名单。
  - 可选文生图（把图片 URL 发到聊天）。
- 自动重登：LittleSkin 会话失效（如 "Invalid access token"）时自动拉起登录流程并重新连接。
- QQ 群聊转述（OneBot 11）：配合 NapCat / Lagrange / go-cqhttp 等网关，在「QQ 转述」页填好网关地址/Token 与群号后，即可把群消息按 `&7&o[群名][昵称]：内容` 的灰色斜体格式发到服务器公共聊天；支持正向连接与反向监听两种模式，图片/表情等非文本以 `[图片]`/`[表情]` 占位；可选把图片保存到本地并由内置 Python HTTP 服务以链接形式发出。
- MC → QQ 反向转述：公屏消息以触发词（默认 `[sentQ]`，可逗号分隔多个）开头即发送到 QQ 群，支持 `[sentQ:群号] 内容` 临时指定群、冷却时间、自动去除 MC 颜色码，非法字符以 `?` 代替；并在公屏回执「转述成功/失败」（话术可配置，支持 `{player}`）。
- 自动重连与踢出处理（**重连/踢出** 页）：连接意外结束（掉线 / 被踢）时按设定延迟自动重连，可设最大次数（重连成功后重置）；被踢出并重连成功后可自动发送 `/lobby`。手动点「断开」不会触发重连。
- 外置登录/网络服务异常友好化：当 LittleSkin 的外置登录接口返回 **5xx**（如 `Response is not JSON. Status code: 504`）、网络超时/不可达时，不再刷一屏原始报错，而是提示「外置登录/会话服务暂时不可用（对方问题）」并按**指数退避**重试（5s→10s→20s… 最高 15 分钟），且同类提示**最多每 60 秒一条**；连上后自动恢复正常。
- 外置登录请求统一 **20 秒硬超时**：OAuth 换 token、角色列表、MC token、以及登录时的 `session/join`（yggdrasil 包，原本用 node-fetch **没有超时**，皮肤站卡住会无限挂起）都改用 `AbortSignal.timeout(20000)`；可用环境变量 `AAF_AUTH_TIMEOUT_MS` 覆盖。
- 界面美化（**界面美化** 页）：可选择一张 PNG / JPG 作为窗口背景图片并调节暗度；字体主题支持「自动（按背景亮度）」/ 浅色背景黑字 / 深色背景白字。
- QQ 网关框架可切换、配置各自独立（**QQ 转述** 页顶部「网关设置」）：默认 **SnowLuma**，可切到 **NapCat**。两者的**启动路径 / 正向地址 / Access Token / 连接模式 / 反向监听**分别保存（`config.json` 里 `qq.snowluma` 与 `qq.napcat` 两个块），互不影响。SnowLuma 会自动从 `<启动路径>/config/onebot_*.json` 读取端口和 token（解决 401）；NapCat 留空路径即用项目自带 `NapCat/`，也支持填自己的 NapCat 目录。
- 账号安全（**QQ 转述 → 账号安全**）：可选自动重连、在线检测间隔；连接因疑似风控被关闭或在线检测连续失败时，明确告警并停止自动重连，避免反复登录加重风控。
- 联网更新提示：启动时后台检查 NapCat 与本程序的最新版本，结果写入**日志**页（NapCat 有新版本、本程序有新提交都会提示）。
- 日志页：原「游戏输出」标签改名为「日志」，每行带 `[时:分:秒]` 时间戳；服务器公告、指令输出等非玩家聊天也会显示（浅蓝 `server` 标签）。
- 低血量报警（**玩家配置** 页）：血量 ≤ 预设值时自动在公屏发言，话术可配（支持 `&` 颜色码）并带冷却。
- 文档转书（**文档转书** 页）：上传 `.docx` / `.doc` / `.txt`，**按书页宽度自动换行、按行数自动翻页**（Java 版每页约 14 行、每本 ≤ 100 页、每页 1024 字为硬上限），由机器人在游戏内把内容写入**书与笔**；可选择**编辑为成书（署名）**，书名模板支持 `{number}`（替换为第几本，只含数字，如 `资本论 P{number}`）；**记录写入进度**（写到第几页/第几本），可**从未写入的地方继续**或**从第 X 册开始**；支持**暂停 / 停止 / 重新写入**；也可**一键清空**书与笔的全部内容。
- 日志保存（底层自动）：日志页里的所有内容——包括服务器聊天、公告/指令输出、私聊、ActionBar 以及程序自身日志——都会在内存中缓存，**每跨过一天或关闭程序时**写入 `logs/yyyy_mm_dd_第N次.txt`（同一天多次保存依次为 第1次、第2次…）。
- 游戏内点歌（**mc-song-mod** 客户端 Mod）：玩家在聊天里发 `[点歌]歌名`（触发词可改）→ **机器人**用会员账号解析出可播放直链、**私聊发回给点歌的人** → 该玩家的客户端 Mod 播放，**谁点谁听**（不打扰别人），而**服务端不需要装任何插件**。机器人不在线时客户端可本地兜底（自己搜网易云）。玩家发 `[点歌]help` 机器人会私聊他全部用法。详见 [`mc-song-mod/README.md`](mc-song-mod/README.md)。（另有 `mc-music-bridge/`：给**自己能装插件**的服务端用的 ZMusic 服务端插件，可选。）

- **修復 #6／安全補領**：首次簽到凍結獎勵與命令，逐項記錄發送狀態。再次簽到只補送確定未送出的項目（含跨日欠發），不重抽或重複計次；已提交、結果未知及舊版無快照紀錄不自動重送。「命令已提交」只代表寫入本機管道，實際到帳請以伺服器為準。未知項目需管理者依日誌及 `checkin_rewards` 紀錄核對。

- **好感度（新功能）**：`[DiaoHelper]好感度` 查询自己的分数/等级/距离下一档还差多少，`[DiaoHelper]好感度 玩家名` 看别人。默认规则：聊天 +1（5 分钟冷却）、点歌成功 +2（1 分钟冷却）、每天首次互动额外 +1；等级 陌生人 → 脸熟 → 熟人 → 朋友 → 好朋友 → 挚友。数据存 `affinity.json`，配置在 `config.json` 的 `affinity` 段（开关/加分/冷却/每日加成都可改）。
- **新增 [`HELP.md`](HELP.md)**：给玩家看的完整说明书（点歌、好感度、视频推荐、幸运值、常见问题、给服主的配置表），也是 `[提示词]帮助` 私聊内容的完整版。
- **视频推荐**：`[DiaoHelper]视频推荐` → **公屏**推一批 B 站视频（标题 + 备注 + **可点击**的链接，点一下开浏览器；有些服务器会显示成可点的「[链接]」）。来源可选：**番剧追番榜（默认）** / **B 站首页推荐**（就是 B 站首页那排，先访问一次首页拿 `buvid3` 再调，避开 `-412 request was banned`） / B 站首页热门 / B 站全站排行 / **我的收藏夹**（填 B 站 Cookie 后可下拉选夹子，**随机翻页抽**）；一次推几条、文案全都能在「杂项」页改。**全服共用冷却**（默认 30 秒，谁点都算），冷却过后再发 = **换一批新的**（从几十条的大池子里挑，先避开刚推过的，越点越多）。来源是**五选一**，选哪个用哪个。
- **今日幸运值**：`[DiaoHelper]今日幸运值` → 当天固定的运气值（上限和文案可在「杂项」页改），**隔天自动刷新**。当天第一次被问到时随机定一个，**存进 `daily.db`**——所以同一天问几次都一模一样，**关掉机器人再开也不会变**。
- **每日签到**：`[DiaoHelper]签到` → 每天一次，公屏回结果 + **发奖励**：金币（可填「最少～最多」随机，还能设连签加成）、物品（id + 数量），奖励怎么发由**两行命令**决定（例：`eco give {player} {value}`、`give {player} {item} {count}`，可用 `{player} {value} {item} {count}` 四个参数），成功 / 已签 / 未开三条文案也能改。连签天数、累计次数记在 `daily.db`，重启不丢。
- **每日数据落库 + 跨天备份**：新增 `daily.db`（SQLite）保存**当天的幸运值**和**谁签到了**；程序发现「库里那天不是今天」就自动把旧库备份到 `db_backup/db_backup_<时间>.db`，然后**删除 + 重建**当天数据（连签统计会带到新库，连签不断）。
- **新增「杂项」标签页**：视频推荐 / 今日幸运值 / 每日签到 的开关 + 文案 + 冷却 + 奖励，以及**群发私聊**——输入一句话、点「发送给所有玩家」，机器人就逐个 `/msg` 所有在线玩家（可设**每个玩家之间的间隔秒数**，防止刷太快被服务器当刷屏踢下线；自动跳过机器人自己）。
- 顺手修：`fabric.mod.json` 的 `minecraft` 依赖改为按版本注入（**修复 26.x 报「不兼容」**，之前所有 jar 都写死 `~1.21.11`）。

### v0.3.0.2

**游戏内点歌（全新，两个方案：默认纯客户端 + 机器人代播，服务端零改动）**

- **客户端点歌 Mod**（新目录 [`mc-song-mod/`](mc-song-mod/README.md)）：**一份源码编 15 个版本**（Fabric **1.21.1 ~ 26.2**），`build_all.ps1` 一键全量构建，产物 `dist/Song_<项目版本>_<游戏版本>.jar`。
  - 1.21.x 用 **mojmap + 重映射 Loom**（`src/legacy`，含游戏内界面）；26.x 未混淆 + 渲染 API 大改 → 非重映射 Loom、Java 25（`src/modern`，无界面）。
  - 聊天入口：`[点歌]歌名`、`[点歌]网易云链接`、`[点歌]歌曲id`；按 **K**（可在「按键设置」改）或发 `[点歌]台` 打开**游戏内「点歌台」**（点歌 / 正在播放 / 我点过的 / 填自己的 Cookie / 停止）。
  - 修掉「正式环境按键没反应」：按键反射里写死了开发期类名 `net.minecraft.client.KeyMapping$Category`，正式环境是混淆名 → 改为**全程不看类名/字段名**的反射（按参数类型匹配构造器 + 取静态实例），1.21.1~1.21.11 通用；注册成功会在日志打 `[songmod] 已注册按键 …`。
  - 播放：优先播机器人给的直链；机器人不在线时**本地兜底**自己搜网易云（`localFallback`，可填**自己的**会员 Cookie 放 VIP 完整版）；`SongPlayer` 手动逐跳处理 `302 https→http`、首帧后再懒建 `SourceDataLine`（修 `0.0Hz/0channels` 打不开）。
- **机器人代播**（新模块 `aafm_py/netease.py`）：机器人用**会员账号**解析歌曲并发给点歌的人，**玩家不用各自登录**。
  - 「点歌」页：**扫码登录**（GUI 里直接画二维码 + 浏览器打开/复制链接）、**验证登录**（显示昵称 + `vipType` 并实测一首会员歌能否拿到完整直链）、Cookie 输入框、代播开关、播放文案模板（`{player}/{music}/{title}/{artist}`）、停止词、Mod 下载链接回复 + 冷却。
  - 会员直链实测结论：老接口 `api/song/enhance/player/url` **带有效 Cookie 本来就认会员**（320k、`trial=0`；不带 Cookie 才只有 30~45s 试听）；eapi（`interface3` + AES-128-ECB）只做兜底。
- **谁点谁听（默认，不广播）**：播放数据用 **`/msg` 私聊**发回点歌的人（`song.privatePlay`），聊天里看不到、别的玩家不跟着响；Mod 侧 `onlyMySong` 双保险（只播**文案里带自己名字**或**自己最近点过**的歌）。两边开关都关 = 全服一起听。
- **快速响应**：`song.instantPlay`（默认开）—— 新点歌**立刻插播**，不再按歌长排队等上一首放完；**同一首歌再点**直接复用刚解析好的直链重播（不再搜索；`_song_recent` 缓存 + 防回声）。
- **`[点歌]help`**：机器人 `/msg` 私聊该玩家全部用法（歌名 / 停止 / 台 / help / 登录·登出 / 网易云链接或 id）。帮助里教的是**全角 `【点歌】`**写法（机器人两种都认，而 Mod 只认半角 `[点歌]`，所以帮助消息不会被 Mod 误当成点歌）；顺手修「`[点歌]台` 被当成歌名叫『台』去搜」。
- **停止按人隔离**：机器人 `[点歌]停止` 只清**该玩家自己**的队列（`clear_song_queue(who)`）；Mod 的 `[点歌]停止`/`[点歌]台` **只认自己发的**（别人发停止不会关掉你的歌）。
- **对抗服务器链接过滤**：有些服务器把 `http(s)://…` 整条替换成 `[链接]`（表现：机器人有输出、Mod 却收不到）。改为发**混淆直链**：`¤`/`¥` 代替协议头、去掉 `?vuutv=…`、`. / :` 换成 `· ¦ ∶`，消息里**不出现** `http`/`://`/`.`，Mod 收到后还原；末尾再附 `id:<歌曲id>` 兜底（直链被改坏时 Mod 用 id 自己取链）。⚠ 不能用 `#`（被服务器当十六进制颜色码吃掉）也不能用 `&`（MC 颜色符）。
- **聊天通道修复**：很多服务器会把玩家聊天**改格式后当「系统消息」重播**（形如 `[称号]名字 » 消息`），这种**只走 `GAME` 不走 `CHAT`** → Mod 改为**同时监听 `CHAT` + `GAME`**；并区分「我发的 / 服务器发来的」，**别人的点歌不再触发我的本地兜底**（以前别人一点歌，我这边 30 秒后也会自己搜一遍）。
- **`/msg` 长度保护**：MC 单包上限 256 是按**整条命令**算的（`/msg ` + 玩家名 + 内容），文案长一点就会被服务器踢（`DecoderException: serverbound/minecraft:chat_command`）。现在预留命令前缀长度，超长自动拆两条，仍超就依次丢 `id:` / 缩歌名 / 退化成「只发 id（Mod 自己取链）」。
- 机器人防自触发/防刷屏：带直链或混淆标记的消息不当点歌、播放模板固定文字跳过、归一化去重、20 秒内超过 12 次忽略；Mod 侧带诊断日志（`[songmod] 收到点歌消息: …` / `用机器人直链播放: …` / 启动版本标记 `obflink5-20261017`）。
- **服务端插件方案（可选）**（新目录 [`mc-music-bridge/`](mc-music-bridge/README.md)）：给**自己能装插件**的服务器用 —— `ZMusicBridge` 按 **ZMusic v5 `zmusic:packet`** 协议自己当服务端下发 `server.play`（无需官方插件/云 API/device_token），支持 `/zmplay 歌名` 与 `[点歌]`。你这种「动不了服务端」的服务器用上面的客户端 Mod 方案。

## QQ 群聊转述

通过 OneBot 11 网关（[SnowLuma](https://github.com/SnowLuma/SnowLuma) 或 [NapCat](https://github.com/NapNeko/NapCatQQ)）把 QQ 群消息转发到 MC 服务器公共聊天。**QQ 转述** 页现在按模块分区：

- **网关设置**：选「启动框架」SnowLuma / NapCat；填「启动路径」；连接模式 / 正向地址 / Access Token / 反向监听；下面一排按钮 **启动 / 快速登录 / 连接 / 重连 / 断开** 与状态。**「连接 / 断开」只控制这个 OneBot 网关本身**。
- **双向转发**（两个方向各自独立开关）：
  - 上半「**QQ → MC**」：**启用 QQ → MC**（群号、转述格式）。**关闭只停止把群消息发进游戏，不会断开 QQ、也不影响 MC → QQ**。
  - 下半「**MC → QQ**」：**启用 MC → QQ**（触发词、目标群、消息模板、冷却、成功/失败提示）。
- **账号安全**：自动重连、在线检测、自动为新扫码账号写配置（仅 NapCat）。
- **图片转本地链接**：图片存 `pic_http/` 并发本地 HTTP 链接。

> **两个框架的配置各自独立保存**（`config.json` 里的 `qq.snowluma` 和 `qq.napcat` 两个块）：路径 / 地址 / Token / 模式 / 监听端口互不影响，切换「启动框架」即切换，可分别修改。

**启动 / 连接**
- 「**启动路径**」：SnowLuma 填它解压后的目录（含 `launcher.bat`/`index.mjs`）；NapCat 填含 `launcher-win10.bat` 的目录。**留空**：SnowLuma 找项目下 `SnowLuma/`，NapCat 用项目自带的 `NapCat/`。程序会自动在该目录找可执行启动文件并拉起。
- **SnowLuma**：在其 WebUI 里登录 QQ 并开「正向 WebSocket（服务端）」，端口默认 **3001**。程序**无需你填对路径**：它会**自动发现正在运行的 SnowLuma 目录**（按运行的 `node.exe`/`index.mjs`），读取 `config/onebot_*.json` 的候选端口/token，并**用真实 WebSocket 握手逐个验证，选用真正能连上的那个**（SnowLuma 重启后文件里的 token 可能失效，会 401，所以不能只读文件）。这样换设备只要 SnowLuma 在跑就能自动连上。日志会打印选中的账号：`[QQ] SnowLuma 账号 UIN=…`。
- **NapCat**：点「启动」调用 `NapCat/napcat/launcher-win10.bat`（弹窗/UAC），并自动打开 `cache` 目录扫码；支持「快速登录」用 `-q <QQ>` 复用会话。程序会**自动为新扫码账号写 OneBot 配置**（`napcat_<QQ>.json` / `napcat_protocol_<QQ>.json` / `onebot11_<QQ>.json`）。
- 「**快速登录**」仅 NapCat 可用（SnowLuma 请在它的 WebUI 里登录）。

**连接后**
1. 点 **连接**：连上后状态显示「QQ 已连接」。**重连** 断开再连；**断开** 停止。
2. QQ → MC：把「群号」填成要转的群（多个逗号分隔，留空=全部群）；群消息按「转述格式」发到公屏。
3. MC → QQ：勾选启用，公屏消息以「触发词」开头即发到「目标群」。触发词可多个（逗号分隔，如 `[sentQ],[-]`），也支持 `[sentQ:群号] 内容` 临时指定群；发送前自动去掉 MC 颜色码、回执「成功/失败提示」（支持 `{player}`）。
4. 反向模式：选 `reverse`，填「反向监听」地址与端口（网关侧配反向 WS 连到本程序，如 `ws://127.0.0.1:3002/onebot/v11/ws`）。正向模式更省事，建议用正向。
5. 可用 `netstat -ano | findstr :3001` 确认端口处于 `LISTENING`。

> QQ → MC 的图片、表情、语音等非文本消息会分别以 `[图片]`、`[表情]`、`[语音]` 等占位符转述。勾选「图片转链接」后，图片会存到 `pic_http/` 并通过本机 Python HTTP 服务发布（只暴露 `/pic_http/` 路径，不会暴露项目根目录），转述文本为 `[图片] http://公网地址:端口/pic_http/文件名`。链接由你自己提供，稳定不过期（除非删文件）。

**账号风控 / 掉线处理**

- 程序会定期（默认每 30 秒，可关）调用 `get_login_info` 检测 QQ 是否在线。
- 若连接因疑似风控/受限被关闭，或在线检测连续 3 次失败，会**明确告警并停止自动重连**，状态显示「QQ 受限/离线」，避免反复登录加重风控；处理完账号后点「启动/重连 QQ」即可恢复。
- 「自动重连」可关闭：关闭后断开不再自动重连。
- NapCat 核心配置（`napcat_<QQ>.json`）没有直接的风控开关；稳妥做法：保持 `autoTimeSync: true`、不要频繁重登、不要刷屏、使用官方 QQ + 较新 NapCat，被要求验证时按手机 QQ 提示完成。

## 文档转书（上传文档 → 游戏内书与笔）

在 **文档转书** 页：

1. 点「选择文件…」选择 `.docx` / `.doc` / `.txt` 文档（`.docx`/`.txt` 无额外依赖；`.doc` 为尽力而为的文本提取，可能有少量乱码）。
2. 设置「每页最大行数」（**上限 14**，Java 版一屏只能放 14 行，会自动锁死）与「每本书最大页数」（默认 100）。**分页只按行数**；程序用保守字体宽度换行并留安全边距，**保证每页不超过 14 行**（签成成书也不会被截断）。超出每本页数会自动拆成多本。
3. 可选填写「开始提示」「结束提示」（会在游戏公屏各说一句），勾选「写完后把书丢出」。
4. 勾选「**编辑为成书（署名）**」后，机器人会把每本**签名成成书**（作者为机器人名），并在「**书名模板**」里用 `{number}` 表示“第几本”（只含数字）。例：模板 `资本论 P{number}` → 第 1 本署名 `资本论 P1`、第 2 本 `资本论 P2`…；不勾选则保持未署名的**书与笔**。
5. 点「预览分页」查看分页结果，点「**写入书与笔**」开始写入（从头开始）。
6. 写入过程中/书与笔用完时：点「**暂停**」「**停止**」会在当前这本写完后停下，并**记录进度**（写到第几页、下一本编号）；点「**从未写入的地方开始写入**」可接着写；点「**重新写入**」从第一页重来。进度保存在项目 `book_progress.json`。
7. 想从**某一册**开始：在控制行「从第 [ ] 册开始」里填册号，点「**从该册开始写入**」——程序从该册对应的页开始，且署名模板 `{number}` 也从该册号开始（例：填 5 → 从第 5 册写，书名 `…P5`、`P6`…）。
8. 点「清空书与笔内容」可删除机器人背包里**所有书与笔的全部页**（只清空内容，不删除书与笔本身）。

原理：机器人调用 mineflayer，找到背包里的**书与笔**并握在主手，然后发送 `edit_book` 协议包把页面写入（不署名时省略 title → 保持「书与笔」；署名时带上 title → 变成成书）。因此：

- 机器人身上需要有书与笔；若在**创造模式**且勾选了「创造模式下缺少书与笔时自动获取」，会自动补一本。
- 生存模式下没有书与笔时会提示失败；多本内容需要对应数量的书与笔（用完后进度会保留，补齐书后点「从未写入的地方开始写入」继续）。
- 需要机器人有权限写入（服务端一般默认允许），部分插件服/反作弊可能拦截。
- 「清空书与笔内容」通过发送空页 `edit_book`（`pages:[]`）清空；创造模式下若服务器未接受，会直接把该书替换为一本全新的书与笔（同样保持未署名）。

> 关于自动翻页（Java 版）：每页最多 **1024** 个字符、每本最多 **100** 页；游戏一屏固定只能放 **14 行**，一行超过约 **114 像素**会自动换行。程序**以「每页最大行数」为准**分页（上限硬性锁死 **14 行**），并按**保守的字体宽度**换行（中文/全角按 10px、英文取上界、并留 2px 安全边距）——宁可每行少放几个字，也**保证每页渲染出来不超过 14 行**，这样签成成书也不会被截断。

## 游戏内点歌

玩法：玩家在聊天里发 **`[点歌]歌名`** → 机器人（会员账号）解析出可播放直链 → **私聊发回给点歌的人** → 他装了「点歌 Mod」的客户端播放。
**谁点谁听**：不广播、不打扰别人；**服务端不需要装任何插件**。机器人不在线时客户端可本地兜底自己搜歌。

| 谁 | 做什么 |
| --- | --- |
| 玩家 | 装 `点歌 Mod`（[`mc-song-mod/`](mc-song-mod/README.md)，Fabric 1.21.1~26.2），聊天里发 `[点歌]告白气球`（也支持 `[点歌]网易云链接` / `[点歌]歌曲id`）；`[点歌]help` 看用法；`[点歌]停止` 停**自己**的。 |
| 机器人 | 在「点歌」页**扫码登录网易云会员**后，看到 `[点歌]` 就用会员账号解析出**可播放直链**，再 **`/msg` 私聊发回给点歌的人**（谁点谁听，默认文案 **`{player} 点了一首 {music}`** + ` \| 混淆直链`，可在「点歌」页改）；该玩家的客户端 Mod 直接播放（**玩家无需各自登录**）；同时记一条**歌曲日志**。 |
| 服务端 | **什么都不用做**（这是纯客户端 + 机器人方案的关键）。 |

- 「点歌」标签页：设**触发词**、**停止词**（默认 `停止`）、**Mod 下载链接**、**回复文案/冷却**；**扫码登录网易云会员**；也可点「点歌」让机器人在聊天里发 `触发词+歌名`。日志页会显示**歌曲日志**（谁点了什么歌）。
- **代播（一次登录，全服共享）**：机器人在「点歌」页扫码登录网易云会员 → 解析出**可播放直链**发回给点歌的人 → 客户端 Mod 直接播放（VIP 歌也能放完整版，**玩家不用各自登录**）。机器人没开/没登录时，客户端可本地兜底（Mod 配置 `localFallback`）。
- **「点歌台」在 Mod 里（游戏内界面）**：装 Mod 后按 **K** 打开，可**点歌**、看**正在播放**与**我点过的歌**、填**自己的网易云 Cookie**（机器人不在线时本地兜底）、一键停止。
- **谁点谁听（不广播）**：机器人侧 `song.privatePlay`（默认开）把播放数据用 `/msg` **私聊**发给点歌的人，公屏不出现点歌消息；Mod 侧 `onlyMySong`（默认 true）只播「文案里带我的名字」或「我最近点过」的歌 —— 所以**即使机器人是公屏发的，也只有点歌的人会响**。想让全服一起听：把两边开关都关掉（机器人 GUI「只放给点歌的人」取消勾选 + `config/songmod.json` 里 `"onlyMySong": false`）。
- 机器人侧负责「**解析 + 发直链 + 排队**」：默认**新点歌立刻插播**（`song.instantPlay`，不等当前这首放完，响应最快）；同一首歌再点会**直接复用刚才的直链重播**（不再搜索）。玩家发 `[点歌]help` 机器人会**私聊**他全部用法（歌名/停止/台/help/登录登出/链接或 id）——帮助里教的是全角 `【点歌】` 写法（机器人两种都认，而 Mod 只认半角，所以帮助消息不会被 Mod 误当成点歌）。
- **为什么公屏上的直链是「乱码」**：不少服务器的聊天插件会把 `http(s)://…` 整条替换成 `[链接]`，Mod 就收不到直链了（表现：机器人有输出，Mod 却要等 30s 走本地兜底）。所以机器人发的是**混淆直链** `¤m801·music·126·net¦…·mp3`（`¤`=http、`¥`=https；去掉协议头、去掉 `?vuutv=…`、把 `. / :` 换成 `· ¦ ∶`），消息里**不出现** `http`/`://`/`.`，绕过链接过滤；Mod 收到后还原成完整直链再播。文案+直链超过 250 字符时会自动拆两条（文案一条、`[点歌]歌名 | ¤直链` 一条）。消息末尾还会附 `id:<歌曲id>`（**不能用 `#`/`&`，会被服务器当颜色码吃掉**），万一直链被改坏，Mod 就用 id 自己取链。
- **Mod 为什么同时监听 `CHAT` 和 `GAME`**：很多服务器的聊天插件会把玩家消息**改格式后当「系统消息」重播**（形如 `[称号]名字 » 消息`），这种只走 `ClientReceiveMessageEvents.GAME`、不走 `CHAT`；只监听 CHAT 的 Mod 会**完全收不到**机器人那条消息。
- Mod 的触发词/音量在客户端 `config/songmod.json` 里改。
- 限制：只有**装了 Mod** 的玩家能听到；音源目前只有网易云（VIP 歌可能拿不到直链）。

> 另有一套**服务端插件** [`mc-music-bridge/`](mc-music-bridge/README.md)（`ZMusicBridge`）：给**自己能装插件**的服务端用，
> 按 ZMusic v5 的 `zmusic:packet` 协议直接向客户端 ZMusic Mod 下发播放。你这种「服务端动不了」的情况用**上面的客户端 Mod**方案。

## 日志保存

日志保存在**底层**自动完成（`aafm_py/log_saver.py` + 控制器），无需手动操作：

- 日志页显示的每一行（服务器聊天、公告与指令输出、私聊、ActionBar，以及程序自身日志）都会带时间戳缓存。
- **每跨过一天**（程序运行中日期变化）以及**关闭程序时**，各保存一次到项目 `logs/` 目录下。
- 文件名形如 `yyyy_mm_dd_第N次.txt`，例如 `2026_10_12_第1次.txt`；同一天再次保存会递增为 `第2次`、`第3次`…（不会覆盖旧文件）。
- 保存成功后会在日志页提示「日志已保存：<文件名>」。
